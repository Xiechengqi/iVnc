# HTTP 本机复制兼容 Review

审查日期：2026-11-12。范围为基于 `0c34484` 的 HTTP 纯文本直接复制、按钮与提示、剪贴板回归脚本及使用文档。整体审查与验证已完成，未发现未处理的阻断问题。

普通 `http://IP:port` 缺少现代 Clipboard API 时，已完整回传的纯文本可以在浏览器用户激活仍有效时通过兼容命令自动复制；激活不足时提示点击一次“复制到本机”，命令不支持或失败时保留手动选择复制。HTTPS 优先使用现代接口，完整流程见 [CLIPBOARD.md](CLIPBOARD.md)。

| 审查点 | 结果 |
| --- | --- |
| 异步回传使用了上一次复制的缓存 | 命令只写入本次完整快照；最初 Ctrl+C 不预写旧值，保留 revision、操作代次及复制后立即粘贴的等待关系 |
| HTTP 自动写入的用户操作要求 | 自动兼容命令要求当前 `userActivation.isActive` 为真；未提供该状态或激活过期时进入点击复制，不猜测固定时限 |
| 临时文本框影响输入焦点和选区 | 使用同步 `copy` 事件提供文本，没有临时文本框，不改变输入焦点、选区及滚动位置 |
| 内部复制事件取消远端粘贴或执行默认复制 | 临时捕获处理器先阻止本次事件默认行为及后续传播；缺少 clipboardData 或设置数据失败时保留快照并显示失败 |
| 命令成功返回但没有实际提供数据 | 必须同时满足命令成功返回、同步事件成功提供数据才报告成功；真实浏览器回归另用原生粘贴验证结果 |
| 监听器泄漏及剪贴板内容存留 | 捕获监听器在 `finally` 中清理；沿用视图内快照生命周期，不增加存储、父窗口传输或包含内容的诊断 |
| 兼容命令绕过已识别页面策略 | Review 中修正检查顺序：HTTP 及现代 API 缺失时也先检查 `clipboard-write` 策略，明确禁止时不执行兼容命令 |
| 现代权限结果晚到覆盖 HTTP 点击提示 | Review 中修正异步权限回调：保留有效的兼容路径提示，不把它退回“HTTP 不支持”提示，不自动重播写入 |
| 现代接口写入被拒绝 | 保留原有权限、页面策略与未知失败处理，不通过兼容命令重试已被拒绝的现代写入 |
| 点击重试与远端剪切 | 在点击调用栈内同步执行，禁止并发重试；不重新向应用发送复制/剪切按键，成功后恢复远端焦点 |
| 空文本、Unicode、MIME 降级 | 空 `text/plain` 可以清空旧内容；Unicode 保持原值；多 MIME 快照仅使用可用纯文本，纯图片显示格式限制并隐藏无效文本按钮 |
| 失焦、外部输入、断线和版本替换 | 沿用可见、活动视图与远端焦点检查；旧写入完成不能清除新快照；断线、关闭同步及本地输入取消旧操作 |

验证使用 Linux Google Chrome **146.0.7680.153**。浏览器测试均使用独立 profile，`Runtime.evaluate` 不伪造用户激活，通过真实鼠标、键盘和粘贴结果验证。完整链路使用独立 iVnc、Wayland Chrome 和 Web 查看器，HTTP 部分直接访问本机实际非回环 IPv4 地址，避免 HTTP 与 WebRTC ICE 解析器的域名映射差异。
