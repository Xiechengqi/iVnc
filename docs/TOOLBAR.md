# 底部工具栏、应用排序与改名

工具栏按“工具、应用、状态”分成三段。网络质量、出口 IPv4 和连接数在右侧正常参与布局，应用区只占剩余宽度；应用多时在自己的容器中横向滚动，不覆盖状态。

## 使用

- 鼠标拖动应用标签或拖动手柄调整顺序。触屏在标签主体横滑浏览，通过手柄拖动排序。应用区溢出时显示左右滚动按钮，鼠标滚轮也可横向浏览。
- 拖动到应用区边缘会自动滚动，可以把应用移到当前屏幕以外。Esc 取消；拖出应用区松开、应用退出或失去窗口焦点也会取消。
- 手柄获得键盘焦点后，左右方向键移动应用。工具栏中的键盘操作不会发送给远程桌面。
- 窄屏下“更多工具”保留其余工具入口。网络状态缩为带状态色的图标，可点击或用键盘打开完整说明。
- 普通状态刷新保留滚动位置；切换应用时把新选中的标签滚动到可见范围。拖动不会重建应用视图或更换当前应用。
- 右键点击托管应用标签，直接打开改名浮层；键盘聚焦标签后按 F2 或 Shift+F10 也可打开。名称自动选中，Enter 保存，Esc、取消或点击浮层外取消；输入法确认不会提交。保存失败保留输入，名称冲突显示当前名称，核对后再次保存才覆盖。
- 在“更多工具”中开启“横滑切换应用”后，可在桌面画面或共享／远程应用画面上用 Mac 触控板双指左右滑动切换标签。触摸屏双指横滑也可使用；关闭时保留原有横向滚动。开关和“反转横滑方向”按当前页面地址保存在浏览器中，默认关闭。纵向滑动仍滚动应用内容，斜向、捏合、拖动、输入法组合以及弹窗交互不会触发切换。每次手势最多切换一个标签，到两端停止；切换时会显示目标应用名。

改名更新应用表中的真实名称，所有窗口和连接到本实例的桌面同步显示。普通窗口以应用名为主，多窗口附带窗口标题，提示保留完整原标题。远程应用在 A 上改名只改变 A 保存的别名。改名保留顺序、PID、启动设置、当前选择、视图令牌及连接。未关联应用记录的窗口没有改名入口；Miao 保持只读，内置 Chrome 可改名。隐藏或禁用控制台以及应用内嵌视图中的权限限制与排序一致。

排序按 iVnc 实例保存，影响所有连接到该实例的桌面及控制台应用表，刷新和重启后保留。A 上调整远程应用顺序不会修改 B。工具按钮和状态不参与排序。没有应用记录的临时窗口排在托管应用之后，保留原有顺序。

一个普通应用的多个窗口作为一个应用组移动，组内维持窗口顺序。底部只显示部分应用，因此排序只置换这些应用原先占据的位置，保留后台、CLI 和未运行应用的位置。例如 `A、后台X、B、CLI-Y、C`，底部拖成 `C、A、B` 后，完整应用表变成 `C、后台X、A、CLI-Y、B`。

排序沿用管理 API 的鉴权、同源校验及控制台访问限制。禁用远程控制台时，远程桌面保留滚动浏览，隐藏排序手柄。

## 数据与 API

SQLite `apps.sort_order` 保存展示位置；旧数据库首次迁移按 `created_at, rowid` 回填，此后打开数据库不会重置顺序。新增应用原子追加到末尾；编辑、内置应用升级保留位置。自启动、恢复运行状态及其他生命周期操作仍按原顺序进行。

`GET /api/apps` 返回按展示位置排列的 `apps`，每项含 `sort_order`，顶层增加 `order_revision`。单项应用查询也返回 `sort_order`。

`GET /api/apps/order` 轻量读取完整顺序：

```json
{"ordered_ids":["app-a","background-x","app-b"],"order_revision":12}
```

`PUT /api/apps/order` 提交完整或可见应用子集的排列：

```json
{"ordered_ids":["app-b","app-a"],"base_revision":12}
```

成功返回完整 `ordered_ids` 和新 `order_revision`。没有变化时版本不变。新增、删除及有效排序更新版本。请求不能包含重复、不存在的 ID 或空列表；字段缺失、类型错误或未知字段返回 `400`（`app_order_invalid`），版本过期返回 `409`（`app_order_conflict`）。全部验证和更新在同一事务内完成，失败不产生部分排序。

前端一次只保存一个排序，保存期间仍更新应用状态。超时、失败或冲突后重新读取服务端顺序；如果读取失败则恢复最后确认的顺序。通过现有 DataChannel `taskbar` 消息向其他桌面广播顺序与版本；同源通知使已打开的控制台立即重新查询，独立控制台的现有 5 秒轮询作为兜底。

### 名称保存

SQLite `apps.name_revision` 保存各应用的名称版本，旧记录迁移为 `0`。它与排序版本独立。应用列表及单项查询返回 `name_revision` 和 `can_rename`。

`PUT /api/apps/{id}/name` 仅修改名称：

```json
{"name":"新应用名","base_revision":3}
```

成功返回 `{"id":"app-id","name":"新应用名","name_revision":4}`。前后空白会去除；名称不能为空，不可包含控制字符或换行，最多 256 个 UTF-8 字节（中文通常占 3 字节）。同名保存不增加版本。校验、唯一性检查、版本比较及名称更新在同一事务内完成。

| 状态 | 含义 |
| --- | --- |
| `400` | 字段缺失、类型错误、未知字段，或名称不合法 |
| `403` | 只读应用或管理权限限制 |
| `404` | 应用不存在 |
| `409` | 名称重复（`app_name_exists`）或版本冲突（`app_name_conflict`） |

版本冲突的 `params` 包含当前 `name`、`name_revision`。前端保留草稿，更新当前名称提示，等待用户明确重试。网络失败或超时会重新查询应用；如果名称已成功保存，则确认结果并关闭浮层。每次只提交一个改名请求，排序请求与改名请求有独立取消控制。

一般配置更新不再写回先前读取的名称。原有远程应用 `PUT /api/apps/{id}` 仍支持改名，使用相同校验和事务，接受 `name_revision` 作为基线；旧客户端省略版本时，以请求开始读取的版本防止请求期间的并发覆盖。控制台只在名称确实变化时提交名称和版本，避免仅修改配置时覆盖外部改名。

名称通知独立于排序版本。DataChannel 推送窗口的名称元数据及流式应用名称版本，同源通知只提示接收方重新读取 API。客户端按每个应用的名称版本拒绝旧响应；名称变化也会触发没有流式应用的桌面广播。编辑中工具栏保持可见；应用消失、删除或工具栏销毁时关闭编辑器并取消相关请求。

## 窗口关联与渲染

普通窗口使用 Wayland 客户端 PID 与活着的托管进程组／祖先进程链关联应用 ID，不使用窗口标题或桌面类名猜测。后台监视器完成 `/proc` 解析与数据库读取，再发布统一内存快照。主合成循环仅读取快照。窗口注册顺序和 `focus,<id>` 保持原有语义；每个窗口另有生命周期内固定的 `window_key`，手势与工具栏通过 `focus-key,<window_key>` 聚焦，避免其他窗口关闭后下标变化导致误选。旧客户端仍能使用下标协议。

`toolbar.js` 负责工具栏 DOM、滚动、排序和切换目标；按标签键复用节点。`gesture-navigation.mjs` 在主桌面和同源应用 iframe 间统一识别手势，按工具栏顺序切换，消费切换后的惯性尾部，避免再次切换或误传给远程应用。`app-streams.js` 继续持有应用 iframe、连接和激活状态。排序版本和窗口归属变化均触发广播，包括没有共享或远程应用时。

## 验证

先构建前后端，再运行：

```bash
cd web/ivnc && npm run build && cd ../..
node scripts/gesture_navigation_smoke.mjs
cargo test --features tls --bin ivnc
cargo build --features tls
IVNC_BIN=target/debug/ivnc node scripts/toolbar_smoke.mjs
ELECTRON_BIN=/path/to/electron IVNC_BIN=target/debug/ivnc node scripts/electron_smoke.mjs
IVNC_BIN=target/debug/ivnc SKIP_BUILD=1 SKIP_UNIT=1 bash scripts/desktop_smoke.sh
IVNC_BIN=target/debug/ivnc bash scripts/remote_app_smoke.sh
```

工具栏 smoke 使用独立数据目录、端口和 Chromium 用户目录，验证 0／1／10／30 个标签、320／375／768／1280／1920 像素宽度、中英双语与 HiDPI、鼠标／触屏／键盘排序、触屏原生滚动、控制台即时通知、失败与版本冲突恢复、保存互斥、拖动自动滚动与取消、真实 GTK 多窗口归属、共享应用连接保持及重启持久化。改名覆盖右键与键盘入口、IME、本地输入隔离、原生菜单、UTF-8 字节限制、重复名称、并发冲突、丢失响应恢复、旧快照、防止自动隐藏、多桌面同步及只读边界。远程回归还验证 A 的别名与 B 的名称独立，改名保留进程和原有视图令牌。需要 `google-chrome`、`gtk3-demo` 和前端依赖中的 `ws`。`KEEP_TMP=1` 保留截图和日志。

横滑回归验证开关关闭时保留原有滚动、开启后按当前顺序单次切换、跨 iframe 惯性不重触发、双指触摸切换、纵向滚动与捏合隔离、全屏指针锁定释放，以及窗口列表下标变化后的稳定聚焦。浏览器自动化覆盖 Chromium；Mac 实体触控板和 Safari 仍需设备实测。
