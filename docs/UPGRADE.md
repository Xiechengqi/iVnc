# 网页升级与 GitHub 代理回退

在“设置 → 重启或升级”勾选“升级到最新版本”并确认后，iVnc 下载对应架构的程序。版本检查与程序下载均自动按以下顺序请求，无需配置：

1. GitHub 原始 URL。
2. 在原始 URL 前加 `https://sina.dev/`。
3. 在原始 URL 前加 `https://httptunnel.top/gh/`。

例如 amd64 程序的第三个请求为：

```text
https://httptunnel.top/gh/https://github.com/Xiechengqi/iVnc/releases/download/latest/ivnc-linux-amd64
```

两个代理分别包装同一个原始 URL，不将代理互相嵌套。原站成功便结束请求；只有当前来源失败才尝试下一个。实现参考 Miao 的 GitHub 下载代理前缀方式，并增加第二级代理及下载过程中的回退。

## 失败与超时

连接失败、HTTP 非 200、响应头超时、下载中断或停滞都会切换来源；版本检查也将 JSON 解析失败或缺少有效版本号视为来源失败。代理返回的 HTML 等错误页、错误架构、过小或不完整的程序不进入安装步骤，而是尝试下一来源。

- 每个来源最多等待响应头 8 秒；版本信息的整个请求最多 10 秒。
- 每次程序下载最多 300 秒，连续 30 秒没有收到数据便回退。每个来源有独立预算。
- 下载日志显示当前来源、切换原因和进度；低速下载定期按已收数据刷新日志。切换来源时进度重新开始，已下载的半成品会清除，不续写其他来源的字节。
- 三个来源全部失败才结束升级并汇总原因；本地创建、写入或清理文件失败时直接报告具体错误，切换网络来源无法修复这些错误。

下载成功前只写安装目录中的临时文件。候选程序必须满足原有最小大小要求，并通过 Linux ELF 64 位格式、当前 CPU 架构及可用 Content-Length 检查。之后沿用现有备份、权限、替换、`--version` 验证与重启流程。全部下载失败时清理临时文件，不进入备份、替换或重启。

## 本地验证

代理回退测试通过本地 HTTP 服务注入错误、超时与中断，使用隔离临时文件，不调用运行实例的升级／重启接口：

```sh
cargo test --lib --features tls --offline web::github_update::tests
cargo test --lib --features tls --offline web::http_server::tests
cargo test --lib --features tls --offline
cargo build --features tls --bin ivnc --offline
cargo fmt --check
git diff --check
```

覆盖直连与两级代理的请求顺序、成功后不再请求、元数据 HTTP／JSON 失败、响应头与响应体超时、下载总超时、连接错误、部分下载与完整重试、错误页和架构校验、无 Content-Length 下载、全部失败清理、本地文件错误，以及代理回退日志的非终止状态。

2026-11-16 实现与 review 结果：Rust 库全部 178 项测试通过，其中新增代理回退与日志检查 15 项；TLS 二进制构建、格式及补丁空白检查通过。审查了请求顺序、完整下载、超时预算、日志等级、临时文件清理及进入安装阶段的条件，已验证范围内未发现阻断问题。验证未调用生产实例的升级或重启接口。

本次外部元数据探测中，`sina.dev` 返回 200，`httptunnel.top/gh` 在当前网络返回 403；两级切换行为通过本地故障注入验证。外部代理实时可达性仍取决于部署网络；三个来源均失败时，升级日志会保留各来源原因。
