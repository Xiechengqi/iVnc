# 远程应用实现 Review

审查日期：2026-11-07。范围为历史规划中的桌面应用共享、应用运行隔离、A→B 中继、控制权、文件传输、迁移和部署；后台 Web/CLI 不作为远程应用导出。

## 实现结果

- 本地与远程桌面应用共用应用视图；远程连接不启动或停止 B 的应用进程。
- B 按应用设置密码与共享策略；A 保存加密凭据。修改密码、关闭共享、删除映射、主动断开和运行代次变化均有撤销路径。
- 每应用独立 compositor、命名空间、HOME、会话总线与 PulseAudio；后台服务按明确授权的 socket 桥接。
- 单控制者、多个观看者，B 所有者可接管；服务端限制输入、剪贴板写入、上传与画面尺寸。
- A 中继 HTTPS/WSS、ICE-TCP 和下载，浏览器的媒体候选仍指向 A；B 编码，A 不重新编码。

## 审查中修复的问题

| 问题 | 修复 |
| --- | --- |
| 下载等待响应时不能随视图关闭取消，失败请求占用会话容量 | 为视图设置独立生命周期，覆盖请求等待、流传输和失败退出；凭据撤销也会取消无 WebSocket 的下载 |
| 重新连接后的关闭按钮仍引用旧视图 URL | 关闭当前保存的 URL，独立页重新连接也清理旧视图 |
| 远程列表一直显示未连接，映射删除/替换遗留凭据 | 返回当前连接状态；尽力撤销 B 的旧凭据，失败创建和测试连接清理临时凭据 |
| 信令队列无界，慢连接可积压 | 改为有容量上限的队列并限制写入时间；媒体队列同样有界 |
| 信令转发写入阻塞时，单个凭据撤销检查可能被推迟 | 在转发循环外独立检查凭据；限制转发与关闭握手耗时，先停止媒体租约再通知客户端 |
| 媒体连接失败或断开后仍保留占用标记 | 连接退出时自动释放标记，允许后续重试；上游连接建立并转发首帧后才显示已连接 |
| 未配置附加 CA 时，WSS 默认加密后端可能因依赖同时启用 ring/aws-lc 而冲突 | 所有 WSS 连接显式使用 ring，保留系统根证书和附加 CA 的校验 |
| 下载根目录/硬链接和特殊文件名处理不完整 | 拒绝符号链接根和硬链接，使用 `openat2` 约束路径，附件文件名使用 UTF-8 百分号编码 |
| 长数据目录超过 Unix socket 路径长度限制 | 通过持有的目录文件描述符定位服务与 slirp socket |
| 旧版 Xwayland 参数不兼容，显示启动等待阻塞合成器 | 使用 `-shm`，在独立启动线程等待 X11 显示，并将应用就绪纳入启动检查 |
| GStreamer 初始化早于工作进程权限收缩 | 先安装防火墙并丢弃权限，再初始化会启动线程的运行依赖 |
| 返回列表时原桌面的声音未同步静音 | 应用视图显示/隐藏时更新原桌面的声音和活动状态 |
| Miao 停止后，其他并发 fork 暂时保留 flock 文件描述符 | 在受管进程组退出后显式解锁；原有生命周期测试加入继承描述符场景 |

另外检查了密码哈希、凭据的应用绑定与认证限流、WebSocket 来源、受限数据路由、上传目录穿越、运行锁和旧代次拒绝、代理 DNS 解析与内网目的地址限制。改变共享开关但省略 desktop 配置时保留原有 X11/服务设置。

## 验证与边界

验证入口与部署方式见 [REMOTE_APPS.md](REMOTE_APPS.md)。本地验证覆盖 Rust 库测试、前端构建、带 TLS 的后端构建、原有桌面回归，以及以下真实进程/浏览器流程：

- 两实例 HTTP 和 HTTPS/WSS 中继，浏览器媒体端口为 A；GTK 画面、点击、上传和下载。
- 无凭据、错误密码、跨应用凭据、越界管理路由、撤销后的请求拒绝。
- 第二观看者绕过前端直接发送接管、尺寸和上传请求仍被服务端拒绝；B 所有者可以接管。
- 关闭共享断开已有视图；删除 A 映射后 B 的应用仍运行。
- 两个独立桌面应用，另一应用私有文件与主实例配置不可见；已授权服务可访问，主实例入口不可访问。
- 私有 PulseAudio、浏览器音频接收、X11 应用画面和输入；停止一个应用不影响另一个。
- 原有 Chrome 启停、自启动偏好和重启恢复。
- 真实 WSS 握手拒绝未受信任的证书，加入指定 CA 后正常收发；不配置附加 CA 时也不会出现加密后端选择冲突。
- 真实 TCP 媒体中继在连接失败后可重试，断线后能重连，撤销后关闭两端连接并释放占用状态。

Docker daemon 在本开发环境不可用，因此提供了 `scripts/remote_app_docker_smoke.sh`，真实容器运行、对外端口发布和跨主机网络验收仍需在有 Docker 的环境执行。未做并发容量或弱网性能基准，保护上限不能作为性能承诺。GTK Wayland/X11 与 Chrome 已有覆盖，任意 Qt/Electron、特殊设备或 GPU 依赖不在本次实测结论内。

公网/NAT 别名必须包含在禁止访问的地址配置中；应用网络规则在启动时生成，地址变更后需要重启应用。允许访问的后台服务保留它原有的管理能力，例如 Miao 全局设置可能影响整个 B 的网络。

本次开发与测试未重启现有的生产 iVnc 实例；实际部署仍需完成上述环境验收。
