# 桌面中文输入与远程应用

工具栏左侧依次为“固定 → 适应窗口／铺满窗口 → 中文输入”。三个入口在窄屏下仍显示；其他工具可以收进更多菜单，恢复宽屏后回到原顺序。显示模式默认“适应窗口”，保留已保存的个人选择；“铺满窗口”开启时背景持续高亮。

## 中文输入偏好与焦点

点击“中文输入”或按 Ctrl+Shift+Space 切换桌面 IME 模式。只有这些用户操作保存开关偏好；页面刷新、应用切换、断线、弹窗或暂时离开页面不会把“暂时停止输入”保存成关闭。

主页面拥有本页的桌面偏好，共享／远程嵌入应用继承该偏好。嵌入应用中的快捷键会更新主页面；它们不会覆盖独立 app-view 页面的偏好。重连使用明确的开启／关闭状态恢复，重复同步不会反向切换。后台页面不能抢焦点，正在编辑本地设置、终端等控件时也不会自动夺走焦点。返回应用后可以继续使用中文输入。

移动端仍以工具栏键盘按钮的用户点击为入口；不会从桌面偏好恢复时自动唤起系统键盘。

## 候选框位置

本机输入代理随当前编辑器报告的光标矩形持续移动，并在工作区、toolbar、全屏、视频尺寸或 Visual Viewport 变化时重新计算。“适应窗口”计入缩放留白；“铺满窗口”分别计算横纵比例。代理保持在可用工作区内，不滚动画面。

应用没有可靠光标元数据时，只能沿用当前目标最近的点击／可靠位置。切换目标会清理旧位置，不使用其他窗口的坐标。popup/subsurface 的坐标无法可靠转换时仍不报告；这类应用无法保证本机候选框始终贴合其内部光标。系统候选窗口最终的外观与屏幕边缘避让由操作系统决定。

## 远程提交与兼容

共享、远程应用使用各自运行时的文字通道。优先把已提交文字送到当前启用的 Wayland text-input-v3；应用未启用时使用有序的粘贴兼容路径。单字符 ASCII 在旧编辑器中仍使用按键。

新版运行时在 `text_input` 状态中增加 `commit:1`。浏览器仅在收到该能力后使用以下扩展：

```text
ti,{"type":"commit","id":1,"focus":"window-uuid","text":"中文"}
ti,{"type":"cancel","id":1}
```

结果只发给请求所属连接，不广播输入内容：

```json
{"type":"text_input_result","data":{"id":1,"status":"dispatched"}}
```

- `dispatched`：已向原生编辑协议发送。不能据此保证应用已接受或保存文字。
- `applied`：粘贴兼容数据已送达应用。应用仍可以拒绝实际编辑。
- `no_focus`、`focus_changed`：没有输入焦点或目标已改变，拒绝送到其他窗口。
- `timeout`、`delivery_failed`、`limit` 等：只在当前活动输入视图提示可操作的失败原因。不显示输入内容，不自动重发不确定的提交。

每个连接的请求 ID 递增且不可重放，最多 32 个待处理提交，单次文字上限 48 KiB。服务端提交有效期为 2 秒；浏览器实际发送后等待回执 3 秒。前序剪贴板传输未完成时不提前消耗回执等待时间。取消操作不等待剪贴板队列；先到的取消也会阻止迟到的同 ID 文字。

应用切换、失焦、覆盖弹窗、隐藏、断线和认证结束会取消组合输入及待确认请求。已经送达应用的文字不能撤销，取消与超时都不会自动重发。没有 `commit:1` 的旧远程服务端继续使用原来的 `t,` 通道；新客户端不能为旧服务端提供目标围栏或提交确认。旧应用的中文兼容性仍取决于粘贴支持。

## 本地验证

```sh
npm --prefix web/ivnc run test:ime
CHROME_BIN=/usr/bin/google-chrome ELECTRON_BIN=/path/to/electron IVNC_WEB_ROOT="$PWD/web/ivnc/dist" node scripts/ime_input_smoke.mjs
```

交互测试覆盖 Chromium／WebKit 的偏好、父子视图、光标映射、取消与显示按钮；端到端测试启动隔离的 A／B 实例，验证真实 Electron 的原生输入、共享旧编辑器的粘贴输入及 A→B 远程输入。测试仅本地执行，见 [CI 约定](CI.md)。macOS 系统候选框、实体移动端键盘及外接显示器仍需要真机验收。
