# 滑动切换应用实现与 Review

日期：2026-11-14。基于 `ea0e850`，范围为默认设置、独立开关、连续横滑识别、异步焦点与回归验证。

## 根因

旧版默认关闭，手势菜单同时提供开启和反转方向两个选项。切换一次后进入 `committed`，每个惯性事件都刷新最后事件时间，必须完全静默超过 260 ms 才能退出。这使新一轮同向和反向滑动也被当作旧惯性吞掉。

工具栏原先只根据服务端最后广播的 `focused` 计算下一个目标。只读浏览器复现中，从 A 连续调用三次下一应用且暂缓焦点广播，三次均请求 B。

## 实现

- 没有保存值时默认开启；原页面地址下显式保存的关闭偏好及 URL 布尔覆盖继续生效。删除反转方向入口及配置读取，方向保持原默认值。
- 独立双向箭头按钮只控制滑动切换；开启高亮，悬停仍保留高亮，提供中英提示、`aria-pressed` 及 Enter/Space 操作。固定按钮仍在首位，滑动按钮在其后；窄屏下两者均保留，其他工具继续使用“更多工具”。
- 保留累计 100 个归一化横向输入单位与方向占优条件。切换后的 100 ms 保护初始峰值；之后用短暂停顿、惯性衰减后的重新增强、明确反向输入识别下一轮，至少两个稳定样本并重新累计触发距离。260 ms 静默仅作为兜底重置，新滑动无需等它到期。微小抖动、独立尖峰及持续衰减不会重复切换。
- 触摸屏通过双指结束事件解除锁定，同一次接触中即使暂停较长时间仍只切换一次。无关视图的触摸清理不会清除触控板滚轮的惯性保护。
- 主页面持有同一个识别器。旧 iframe 可以排空惯性并提供衰减信息，只有当前活动视图可以发起下一次切换。新的纵向手势恢复普通滚动，修饰键、捏合、拖拽、输入法组合和弹窗保护继续生效。
- 工具栏分别保存实际焦点与最新导航意图。意图在调用激活前写入，兼容 iframe 激活同步回调；后续滑动立即从意图目标继续。中间广播继续更新实际视图，但不改写最新导航目标。返回仍然显示旧焦点的应用时，普通元数据刷新不能过早把请求当作已确认。
- 待确认 tab 仅显示细边框及 `aria-busy`，实际焦点、输入与剪贴板目标继续依照真实活动视图。提示立即更新，不等待动画或上一条提示。同步更新已重绘时避免再次绘制。
- 直接点击覆盖旧意图；目标消失、变得不可用、断线、页面隐藏、关闭手势及 2 秒超时清理状态。发送桌面聚焦失败时保留原活动 iframe。定时器、监听器随工具栏销毁释放，标签排序和切换不重建已有视图连接。

## 验证方法

```bash
node scripts/gesture_navigation_smoke.mjs
node --test scripts/video_playback_test.mjs scripts/viewport_test.mjs scripts/clipboard_test.mjs
CHROME_BIN=/usr/bin/google-chrome npm --prefix web/ivnc run test:toolbar
CHROME_BIN=/usr/bin/google-chrome npm --prefix web/ivnc run test:viewport
npm --prefix web/ivnc run build
cargo build --features tls --bin ivnc --offline
IVNC_BIN=target/debug/ivnc node scripts/toolbar_smoke.mjs
ELECTRON_BIN=/path/to/electron IVNC_BIN=target/debug/ivnc node scripts/electron_smoke.mjs
```

原生浏览器专项使用真实 toolbar、app-streams 和手势模块，模拟 API 与延迟广播。DPR 2 下先测量各引擎原生滚轮注入的 DOM 单位，再以相同归一化输入重放序列。连续序列覆盖约 160 ms 间隔的桌面／共享／远程切换及原 iframe 保留；不把页面运行耗时当作实际视频延迟。

真实实例 smoke 使用隔离的数据库、端口、浏览器目录及 Wayland 应用。刷新偏好测试等待首帧后才注入画面输入。Electron 脚本的输出调整改用现行的带 revision 管理 API，替换已经不再改变共享输出的旧 `r,` 消息。

## 整体 Review

已审查默认值与已有偏好、按钮单一职责及窄屏布局、惯性重入与旧视图隔离、双指生命周期、异步确认与反向导航、点击优先级、稳定窗口 key、顺序变化及目标移除、失败／超时／后台隐藏／断线清理，以及视图连接复用。

实现中补齐新纵向手势提前退出惯性抑制、无关触摸清理不重置滚轮保护、返回旧实际焦点时防止提前确认，以及同步焦点更新时避免重复绘制。导航状态不会替换实际键鼠和剪贴板目标。

结合差异审查、回归结果及截图核对，未发现剩余阻断问题。

浏览器标准没有统一提供触控板接触阶段和惯性标记，因此分段依赖输入序列判断。Linux Chromium/WebKit 自动化不能替代用户 Mac 的实体触控板与具体 Safari 版本体验验证；首开远程视图的连接与视频首帧耗时需与手势响应分别评估。
