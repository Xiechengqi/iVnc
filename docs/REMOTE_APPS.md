# 远程桌面应用

iVnc 可以把 B 上的一个桌面应用共享给另一台 iVnc（A）。A 把它添加为“远程应用”，启动后它和本机应用一样以标签形式出现在 A 桌面的工具栏中。用户浏览器只连接 A，A 中继 B 的信令和 ICE-TCP 媒体；画面由 B 编码，A 不重新编码。

## 使用

在 B 上共享应用：

1. 为 B 设置非默认的实例管理密码（未启用认证或仍使用示例密码时不能开启共享）。
2. 在控制台“编辑”桌面应用，在“远程访问”部分打开“允许远程访问”，设置访问密码（8–256 字节，可点“生成”，可显示/隐藏），保存。
3. 同一部分显示连接地址（`https://B/remote/v1/apps/<id>`），复制它和访问密码交给 A。
4. 应用正在运行时，保存后提示需要重启，应用列表显示“共享 · 需重启”；点“立即重启”或稍后自行重启。重启后应用在独立运行环境中运行并显示“共享中”，此后才接受远程连接。

在 A 上使用：

1. 新增“远程应用”，填写连接地址和访问密码，可选填本地名称；“测试连接”显示目标应用名称及其状态（运行中、对方应用启动中、对方应用需重启或未运行）。
2. 在应用列表中“启动”远程应用即连接 B 上已运行的进程，桌面工具栏出现它的标签并自动切换过去；“停止”断开连接并移除标签。A 不能启动或停止 B 上的进程。
3. 远程应用的启动状态与本机应用的运行状态一起保存，A 短时间内重启（5 分钟内）后已启动的远程应用自动重新连接。需要一直连接的远程应用勾选“开机启动”，与本机应用一样在 iVnc 每次启动时自动启动（连接）。

共享默认关闭。公网地址必须使用 HTTPS；明文 HTTP 只接受回环和私有 IP 地址，用于可信内网或本地测试，A 的应用列表对这类远程应用标记“未加密”。A 不能把自身实例添加为远程应用。

### 运行方式

| 桌面应用 | 运行方式 | 在本机桌面中 |
| --- | --- | --- |
| 未开启远程访问 | 主桌面合成器的 Wayland 客户端 | 工具栏中的窗口；启动后显示其窗口 |
| 开启远程访问 | 独立运行环境（worker）：自带合成器和私有 PulseAudio，应用是 worker 的普通子进程 | 工具栏中的应用标签，本机也通过同一应用视图查看和操作 |

两种方式下应用的文件、网络和环境完全相同：使用同一个应用 HOME（`apps/<id>/home`，内置 Chrome 因此保留同一个用户配置），以 iVnc 的运行用户访问主机文件系统和主机网络，应用环境变量由同一段逻辑生成（继承的变量、应用配置的变量及其默认值都相同），只有指向合成器、运行目录和音频服务的 `WAYLAND_DISPLAY`、`XDG_RUNTIME_DIR`、`PULSE_SERVER` 随运行方式不同。没有沙箱、命名空间、网络或文件隔离。只支持 Wayland 应用，不提供 X11/Xwayland。

开启远程访问即允许持有密码的人完全操作该应用：在 Chrome 中打开文件对话框、在终端中执行命令等，都以 iVnc 运行用户的权限作用于 B。只共享可以交给对方完全操作的应用。远程用户在应用内关闭窗口、退出程序等操作也会实际作用于 B 上的应用。内置 Chrome 的 DevTools 端口（`0.0.0.0:9222`）与共享无关，应按原有方式由防火墙限制。

运行方式只在应用启动时决定。开启或关闭远程访问时应用若在运行，会继续以原方式运行到重启，列表显示“需重启”；开启后、重启前 B 拒绝新的远程连接，A 显示“对方应用需重启”。

### 工具栏标签

桌面工具栏除主桌面的窗口外，还列出本机正在共享的桌面应用和已启动的远程应用（DataChannel `taskbar` 消息的 `apps` 字段，见 [协议](PROTOCOL.md#53-任务栏消息-taskbar)）。选中标签时，应用视图以内嵌页面覆盖在桌面画面上（固定工具栏时位于其上方）；切换到其他标签时视图保持连接，声音继续播放，并释放按住的键。上传和输入法按钮作用于当前标签。应用标签覆盖桌面期间，桌面页面向主桌面报告自身不可见，主合成器因此可以空闲；切回窗口标签或该标签消失后恢复为可见。主桌面的输入和声音不受影响。在控制台启动的应用出现时自动切换到它的标签；随 iVnc 自启动的应用不会。

每个浏览器页面为每个应用申请自己的视图令牌，一个令牌对应一个连接；页面关闭时只关闭自己的视图。视图被撤销后，点击标签重新连接；B 的应用重新运行或视图过期后页面自动申请新令牌。

### 多个连接

同一应用可以同时被多个连接查看：A 的多个浏览器页面、多个 A 以及 B 本机。所有连接共用同一个应用进程，每个连接都可以操作，没有控制权分配。上传的文件保存到应用 HOME 的 `Downloads` 目录；应用视图不提供下载。

| 操作 | 行为 |
| --- | --- |
| A 停止远程应用 | 断开 A 上该应用的全部视图并移除标签；B 的应用继续运行 |
| A 删除远程应用 | 删除连接配置；B 的应用继续运行 |
| A 重启 | 保留连接配置；5 分钟内重启时已启动的远程应用重新连接，勾选“开机启动”的远程应用每次都自动连接 |
| B 关闭共享或修改访问密码 | 立即断开所有远程会话；B 本机访问保留。修改密码后 A 显示“需重新输入密码” |
| B 停止或重启应用 | 会话结束，A 显示“对方应用未运行”，B 的运行环境启动期间显示“对方应用启动中”；应用就绪后 A 重新连接 |
| B 的应用未运行 | A 显示状态，不提供远端启停 |

A 的应用列表显示远程应用状态：未启动、连接中、已连接、对方应用启动中、对方应用未运行、对方应用需重启、需重新输入密码、版本不兼容、无法连接。“对方应用启动中”表示 B 的应用已开启共享、运行环境仍在启动，不是错误，就绪后自动连接。状态在后台更新，最长缓存 30 秒。

### 进程与日志

应用由启动命令的整个进程树组成：启动命令在专用的回收进程下运行，启动器派生进程后退出不会结束应用，最后一个应用进程退出时应用才停止。意外退出的应用由看护进程重启；运行不足 30 秒即退出视为启动失败，重试间隔从 6 秒起倍增，连续 5 次失败后停止重试并显示为崩溃。共享应用的运行环境启动失败时，控制台直接显示原因。

应用日志位于 `apps/<id>/app.log`，以追加方式写入，超过 8 MB 时在下次启动前轮换为 `app.log.1`。共享应用的运行环境日志也写入该文件。

## 访问控制

- B 保存访问密码的 Argon2 校验值，以及一份用 `remote.key` 加密的副本，因此可在编辑窗口中查看。从旧版本升级的密码只有校验值，显示“已设置但无法查看”，仍然有效；重新设置后即可查看。
- A 用访问密码向 B 换取一个短期会话令牌。令牌只保存在 B 的内存中，绑定该应用当前的共享策略版本，空闲 12 小时后失效；每个应用保留的令牌数有上限，超出时只淘汰该应用最旧的令牌，不影响其他应用；令牌失效或 B 重启后，A 用保存的密码自动重新认证。A 加密保存访问密码，应用列表不返回密码。
- 关闭共享或修改密码会更新策略版本：已签发的令牌全部失效，正在进行的信令和媒体立即断开。要终止所有远程访问，关闭共享或修改密码即可；没有已保存连接列表、逐个撤销或会话断开功能，也不写审计日志。
- 访问密码错误按来源限流（IPv6 按 /64 计）：同一来源对同一应用 15 分钟内失败 8 次、对所有应用失败 30 次后暂时拒绝；进行中的尝试先按失败计数，认证成功后扣除。某个来源的失败不会锁住其他来源。同一应用的密码校验串行进行，每次失败额外占用 1 秒，因此不论来源多少，针对单个应用的猜测约为每秒一次。未共享的应用直接拒绝，不消耗密码校验资源。所有来源都经反向代理时会共享同一计数，因此应直接或经四层入口访问。

## 部署与证书

共享应用的运行环境不需要额外的内核功能或权限，只依赖 PulseAudio 提供私有音频：

```bash
sudo apt-get install pulseaudio pulseaudio-utils
bash build.sh --release --features tls
```

Docker 镜像已包含这些依赖、音频捕获及 TLS。容器不需要额外的 `--security-opt`、`--cap-add SYS_ADMIN`、`--pid=host` 或 `--privileged`；`docker-run.sh` 中的 `--device /dev/net/tun` 与 `NET_ADMIN` 只供 Miao 的 TUN 代理模式使用。

A 和 B 都只需一个入口端口，但该端口必须支持 HTTP(S)、WebSocket 和原始 ICE-TCP。支持直接 TCP 连接、Docker 端口发布及能透明转发这些流量的四层入口。只转发 HTTP/WebSocket 的反向代理或 CDN 不适用于当前媒体通道。A 必须能访问 B；没有自动 NAT 穿透或反向隧道。

`--tls` 默认在 `$IVNC_HOME/tls/` 首次生成并持久化证书，重启复用。生产环境可指定可信证书：

```bash
IVNC_TLS_CERT_FILE=/etc/ivnc/cert.pem \
IVNC_TLS_KEY_FILE=/etc/ivnc/key.pem ivnc --tls
```

| 环境变量 | 含义 |
| --- | --- |
| `IVNC_TLS_CERT_FILE` / `IVNC_TLS_KEY_FILE` | PEM 证书链与私钥，必须同时指定；文件更新后 60 秒内自动加载，无需重启，新文件无效时继续使用旧证书 |
| `IVNC_TLS_NAMES` | 首次生成证书时附加的 DNS/IP SAN，以逗号分隔；不会修改已存在的证书 |
| `IVNC_REMOTE_CA_FILE` | A 信任 B 的附加 PEM CA/证书集合，与系统根证书一起用于 HTTPS 和 WSS；仍校验证书名称；文件更新后下次连接时重新加载 |

私有证书的示例：在 B 首次启动时设置 `IVNC_TLS_NAMES=b.example`，将其证书通过可信途径复制给 A，A 设置 `IVNC_REMOTE_CA_FILE=/etc/ivnc/b-ca.pem`。用户浏览器访问 A 的 HTTPS 时还需要独立信任 A 的证书。不要复制 B 的私钥给 A。

## 数据与升级

- `apps.db` 保留应用 ID、启动配置、自启动偏好和原目录。`app_running_state.json` 记录运行中的应用和已启动的远程应用，用于重启恢复。
- `remote.db` 保存节点身份、共享策略（开关、密码校验值与加密副本、策略版本）以及 A 的远程应用连接信息（含加密的访问密码）；`remote.key` 是本机加密密钥。两者权限为 `0600`，需一起备份。
- `apps/<id>/home` 是应用 HOME，两种运行方式共用；`apps/<id>/worker-state` 是共享应用运行环境自身的状态目录。
- `runtimes/<id>/` 保存共享应用的运行代次、内部端点和最近一次启动失败原因，删除应用时一并删除；不是可对外发布的 API。

从带应用隔离的版本升级时，`remote.db` 在首次启动时迁移一次（`PRAGMA user_version` 由 0 变为 1）：

- 删除已保存连接（`grants` 表）；B 的共享开关和访问密码保留，原密码仍可使用但无法查看。
- A 的访问密码改存在新的字段中，不再读取旧版本保存的凭据；旧连接显示“需重新输入密码”，在 A 编辑该应用并重新输入访问密码即可。回退到旧版本期间新增或修改过的连接，回到新版本后同样可能需要重新输入密码。
- 删除 `remote-audit.log` 及其轮换文件。旧的隔离设置留在数据库中但不再读取，便于回退。
- 未开启远程访问的桌面应用重新作为主桌面窗口运行，开启远程访问的应用继续在独立运行环境中运行。旧版本留下的 `apps.before-isolation.db` 和 `public-ipv4` 不再使用，确认无需回退后可以删除。

每实例限制 128 个活动应用连接/数据请求和 128 个打开的应用视图；没有连接的视图空闲 8 小时后失效，使用中的视图不受时长限制。媒体和信令队列有容量限制：短暂拥塞时丢弃媒体包并在恢复后请求关键帧，持续拥塞 10 秒的连接才会关闭。这些是保护上限，不代表该数量的并发性能保证。

## 验证

先构建当前代码，再明确指定待测二进制：

```bash
export IVNC_BIN="$PWD/target/release/ivnc"
bash scripts/remote_app_smoke.sh
REMOTE_SMOKE_TLS=1 bash scripts/remote_app_smoke.sh
bash scripts/remote_hardening_smoke.sh
IVNC_BIN="$IVNC_BIN" SKIP_BUILD=1 SKIP_UNIT=1 bash scripts/desktop_smoke.sh
```

测试依赖包括 `gtk-3-examples`、Chrome、Node.js、Python 3、jq、curl 和前端的 `ws` 包（`npm ci --prefix web/ivnc`）。远程测试创建两个临时实例，验证共享密码、A 启动远程应用、经 A 中继的视频和输入、多个连接同时操作、上传、内嵌视图（隐藏工具栏、连接指示和状态栏，并向父页面报告就绪和连接状态）以及关闭共享后的断开；加固测试验证运行方式切换与需重启提示、两种方式下相同的文件/网络/环境、启动器进程、崩溃退避、密码查看与修改、A 的状态与重新输入密码、限流和证书配置。测试不操作已有 iVnc 实例。

Docker 验证入口（也可在 GitHub Actions 手动运行 “Remote application runtime smoke”）：

```bash
docker build -t ivnc:remote-review .
IVNC_TEST_IMAGE=ivnc:remote-review bash scripts/remote_app_docker_smoke.sh
```

容器测试在一次性容器中安装测试工具并运行双实例和加固套件。对外发布端口、不同主机网络和负载容量还需在实际部署环境验证。
