## 发现与修正

| 问题 | 修正与验证 |
| --- | --- |
| UUID 应用目录内的 TMPDIR 使 Chrome 原生 socket 路径超过 Unix socket 限制，真实浏览器崩溃 | 改为带运行用户和应用根目录哈希的短专属临时路径，检查 0700 权限与归属；真实主桌面和共享会话中的 Chrome 均能打开窗口 |
| 编辑运行中的目录或调试端口后，仅检查新配置会失去对旧资源的保护 | 进程持有实际资源租约直到整棵进程树退出；回归验证运行中修改 A 后旧端口仍不能分配给另一个应用 |
| 清理固定内置目录和全局 Chrome 临时数据会误伤其他实例或宿主机浏览器 | 按应用配置解析目录，清理与启动共享资源锁；取消全局临时文件扫描及宿主机 sidecar 清理；真实回归验证清理 A 不影响 B、保留 A 的扩展 |
| 外部目录的全量重置及符号链接可能突破数据边界 | 外部目录只开放已确认归属的类别清理；拒绝完全重置和链接父目录遍历，处理嵌套目录去重 |
| 手动命令仍被自动参数或配置改写 | 原样保存手动命令并绕过 Electron 参数适配；停用配置参与启动和推断清理，切回生成模式前确认 |
| 旧版自定义命令或失效配置可能在注册时被覆盖，外部目录不可用可能阻止 iVnc 启动 | 严格识别标准旧模板，其余保留手动命令；保留不可用的已存结构化配置，服务可启动供用户修正；初次注册默认端口冲突时关闭内置调试端口 |
| 外部 profile 尚未由应用启动建立标记时，无法删除应用记录 | 删除采用只保护应用根目录的独立锁，保留未认领或不可用的外部数据；API 回归覆盖目录和临时不可用的两种情况 |
| 直接把带 shell 赋值的命令写入 Desktop Entry 的 Exec 无法正确运行，固定临时文件名也会产生并发冲突 | 使用稳定应用 ID 的入口和私有脚本，按唯一临时文件原子替换；确认新入口成功后严格识别并移除旧版内置入口，保留自定义入口 |
| 安装检测可能阻塞、输出过量或遗留 Shell 启动文件派生的后台进程 | 检测限时 2 秒、输出上限 64 KiB、短时缓存，并回收独立检测进程组；测试验证权限、Shell PATH 和子进程清理 |
| 既有 socks5h 配置可能被新后端校验拒绝 | 保留协议兼容，转换为 Chromium 原生 SOCKS5 参数；命令生成回归通过 |
| 安装状态和预览的异步结果可能改写后来打开的弹窗，刷新选项可能打断点击 | 请求取消、弹窗实例和序号校验，保存稳定草稿 ID；更新原有选项节点，晚到响应及展开下拉框点击回归通过 |
| 移动端手动命令复选框被通用输入框样式放大，英文 tooltip 导致横向溢出 | 复用紧凑 checkbox 行样式，窄屏分行排列选项、调整 tooltip 锚点；320px 中英文截图与尺寸断言通过 |

## 已知边界

- 生成模式面向 `google-chrome`；自定义浏览器 binary、任意 shell 包装和自定参数使用手动命令模式。
- 目录配置变更不自动搬迁用户数据，运行中应用需要重启后采用新配置。手动命令的实际 profile 无法可靠推断，因此不支持自动目录清理。
- 调试端口会检查配置冲突和启动前占用；其他非 iVnc 进程仍可能在检查后抢占端口，Chrome 的实际启动结果为准。
- 选择性清理当前覆盖 Chrome 的已知 Default profile 条目；新增格式及未知条目保留。网站与扩展共用的本地存储默认不清理，显式选择该类别会影响二者。
- 已验证 Chromium 与 WebKit 引擎和真实 Linux Chrome，没有进行 macOS Safari、iPad 实机测试，也未用外部代理验证实际联网。
