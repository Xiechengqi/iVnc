# 移动端键盘与文字输入

移动端工具栏的键盘图标用于显示／收起当前应用的系统键盘。只有用户手动点击此按钮才打开移动输入；点击应用画面、收到编辑状态、页面加载、刷新、应用切换或重连均不自动弹出键盘。桌面端保留中文 IME 按钮和 Ctrl+Shift+Space；其偏好保存、光标跟随和远程输入回执见 [桌面中文输入](IME_INPUT.md)。

## 触屏手势

画面铺满视口，没有浏览器页面可滚。下列手势按触点事件识别，不读取 User-Agent，因此 iPad 桌面网站模式、外接鼠标和触控板滚轮保持原有路径。

- 单指按下后先不发送移动或按键。位移不超过 10 像素、抬手且时长不超过 250 毫秒时，在起点发送一次左键点击。滑动期间的轻微抖动不改变点击位置，也不提前发出按下。
- 纵向位移先达到 10 像素，且不小于横向位移时进入滚动。进入时先在起点发送一次按下并立即松开，让切换后的应用窗口或浏览器标签获得焦点；之后的触点增量进入滚轮通道，并在速度滑块之前乘以 2.5。速度为 1 时，手指移动 48 像素约等于一个 120 像素滚轮刻度。抬手不再发送点击，也不保持左键，也不切换应用。
- 按住时滚过的距离只跟手指路程走。抬手速度只看最后 100 毫秒：低于每毫秒 0.22 CSS 像素时视为缓慢滑动，立即停止；达到该速度时视为快速滑动，沿最后方向继续滚动，最多 1.5 秒、2400 CSS 像素，并逐渐衰减。单指和双指滚动共用这段惯性。新的触摸、切换应用、页面隐藏、失焦、弹窗、几何变化、断线和修改滚动速度都会清掉尚未发出的余量。鼠标滚轮和系统触控板不再叠加。
- 横向位移先达到 10 像素，且大于纵向位移时保持拖动，用于选择、拖拽和滑块。
- 长按右键仍是 750 毫秒且移动不足 15 像素。进入滚动或拖动后取消长按。
- 滚动过程中出现第二指时结束单指滚动且不补发点击，随后沿用双指滚动。双指轻点仍是右键，双指横滑仍切换应用。
- 终端弹窗单独把单指滑动转成终端历史滚动。工具栏标签、按钮和菜单不进入远端滚动。

## 操作与兼容

- 点击键盘按钮，在本次用户点击中同步聚焦本地编辑代理。共享应用和远程应用的同源嵌入视图使用同步调用，避免异步消息丢失 iOS 的键盘唤起机会。
- 支持 text-input-v3 的应用会报告当前编辑状态，用于选择数字、邮箱等键盘布局和定位光标。单指点击仅操作远端应用，编辑状态即使紧随点击到达也不唤起系统键盘。
- 用户手动收起或本地输入代理失去焦点后，移动输入保持关闭，直到再次点击键盘按钮；已经手动打开键盘时，点击应用画面仍可移动远端光标并继续输入。此行为同样适用于 iPad 桌面网站模式及外接鼠标。
- 英文、数字、中文候选、emoji 共用一个文字输入代理。文字通过 DataChannel 提交，支持原生文字协议的应用直接接收；回车、删除和导航键保持按键语义。新版运行时提供提交回执，旧版保留 `t,` 通道。
- 未启用文字协议的旧应用，单字符 ASCII 使用按键兼容路径，避免每个字都发生剪贴板事务；Unicode 和较长文字沿用已有串行文字兼容通道，其支持范围仍取决于应用是否接受粘贴。
- 默认关闭本地自动纠错、自动大小写和拼写检查。本地代理不持有远端完整文档，也不读取远端密码或周边文本。

## 键盘遮挡与应用切换

顶层页面同时观察布局视口和 Visual Viewport，按实际可视宽度定位工作区。系统键盘弹出后画面保持原来的尺寸，键盘盖住下方；远端光标或本次点击位置会落到键盘和工具栏后面时，整幅画面连同点击层上移，让光标下沿留在工具栏上方并空出一行。光标本来就在上方时画面不动。键盘收起后回到原位，上移使用短过渡，系统开启减少动态效果时立即到位。外接键盘没有把可视高度明显缩短时不移动画面。嵌入视图继承父页面工作区，不再次扣除工具栏。缩放手势不会按键盘遮挡处理。适应窗口按比例缩放；铺满窗口先保持视频源比例，再用 CSS transform 分别拉伸横纵轴，避免 Safari 视频原生层只保持比例而裁掉两侧。光标更新不滚动查看区域，不更改其他客户端的远端桌面尺寸。固定工具栏仍贴在键盘上沿。

切换应用、失去页面焦点、打开覆盖弹窗、断开连接及退出登录时，取消未提交的组合输入并清理按键状态。后台视图不能自动夺取编辑焦点。系统收起键盘造成可视区域恢复时，输入代理与按钮状态随之复位。

## 编辑状态协议

服务器通过现有 DataChannel 下发：

```json
{"type":"text_input","data":{"protocol":1,"commit":1,"enabled":true,"focus":"window-uuid","purpose":0,"cursor":[100,200,1,18]}}
```

`enabled` 来自当前焦点客户端提交的 text-input-v3 状态。`purpose` 沿用 Wayland content purpose，用于数字、电话、URL、邮箱等键盘布局。`cursor` 使用远端桌面逻辑坐标；无法可靠转换的 popup/subsurface 返回 null。消息不包含 surrounding text、选区内容或输入文字。状态变化和新 DataChannel 建立时发送。

`commit:1` 表示支持带目标窗口 UUID、请求 ID 和取消操作的文字回执扩展；这是独立于 Wayland 编辑器 `enabled` 的运行时能力。完整消息见 [桌面中文输入](IME_INPUT.md)。前后端仍接受原来的文字／按键消息。旧客户端可以忽略新增状态；旧服务器下仍可使用手动键盘入口。

## 验证

```sh
CHROME_BIN=/usr/bin/google-chrome node scripts/mobile_input_test.mjs
CHROME_BIN=/usr/bin/google-chrome ELECTRON_BIN=/path/to/electron node scripts/mobile_input_smoke.mjs
```

前者验证生产输入、视口和共享应用模块；后者通过真实 WebRTC 将移动浏览器输入送入 Electron Wayland 编辑框，并覆盖独立共享运行时。Linux Chromium／WebKit 自动化验证不等于 iPhone、iPad 或 Android 真机系统键盘验收。

未设置 `CHROME_BIN` 时使用 Playwright 安装的 Chromium。移动输入交互套件在本地执行，GitHub Actions 不再运行 UI 测试，见 [持续集成与本地验证](CI.md)。端到端脚本对 Chromium 强制等待画面；Linux 无头 WebKit 的画面展示可能受运行环境限制，脚本单独输出媒体诊断后继续检查文字链路。设置 `REQUIRE_VIDEO=1` 可对两种引擎都要求实际画面。
