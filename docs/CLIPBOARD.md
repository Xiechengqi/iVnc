# 剪贴板与粘贴事务

本机复制后第一次在远端粘贴必须使用本次内容。原实现先转发 V 按键，随后在浏览器 `paste` 事件里发送 `cw`；服务端又把两者分入不同队列。因此远端可能先粘贴旧内容，下一次才使用新内容。固定延时、1 秒节流和“每轮先处理剪贴板”都无法提供顺序保证。

## 当前流程

1. `input2.js` 识别 Ctrl/Cmd+V、Ctrl+Shift+V 和 Shift+Insert，交给 `clipboard.js` 捕获用户原生 `paste` 事件，不提前发送 V。本地 toolbar、表单和 Web 终端保持原生输入。
2. 一次手势保存内容、快捷键类型和目标窗口。后续键盘/鼠标输入按顺序排在这次操作后；使用 `event.repeat` 抑制长按，不按时间吞掉独立粘贴。
3. 同一有序输入 DataChannel 上协商能力，发送 `paste` 的 start/chunk/commit。文本按 UTF-8 字节分块，空文本合法。默认关闭的二进制开关启用后，同次传输也可保存 HTML 和 PNG。
4. start 在合成器输入队列中绑定实际 `WlSurface`，commit 只在完整长度、UTF-8、期限和目标校验通过后执行。应用关闭、焦点改变、取消或连接结束后的操作不迁移到别的窗口。
5. 合成器先建立独立 `Arc<[u8]>` selection，再派发对应快捷键，并恢复之前持有的修饰键。每份 Wayland offer 保留自己的内容，后来的粘贴不能改变旧 offer 的读取结果。
6. 应用请求读取 offer 后，内容异步写入管道并关闭写端（EOF），才向请求连接返回 `paste_ack`。`applied` 确认 selection、按键派发和管道交付，**不表示 Chrome 的异步文本插入已经完成**。写入失败或超过 10 秒返回 `delivery_failed`；应用始终不读取时由 30 秒操作期限结束。客户端不自动重试。

真实 Chrome 验证还发现，仅在按键派发后确认会使快速 A/B 粘贴复用尚未完成的第一次读取，得到 AA；将确认放在管道关闭之后，连续粘贴得到预期 AB。同一 seat 的其他连接在前一次交付结束前发起事务时返回 `busy`，避免覆盖尚未读取的 selection。

每条连接使用单调递增操作 ID。相同 ID 不会再次执行；相同文本的新手势仍会执行。浏览器端最多保留 16 MiB 待粘贴文本，单条请求最多 16 MiB、单块 12 KiB，传输/确认超时 30 秒。服务端限制待执行请求数；Wayland 输出采用独立单线程异步执行器、最多 64 个并发写入及 10 秒写入期限，避免慢应用阻塞合成器。

## 双向同步和生命周期

- 每次 selection 变化增加 revision。异步读取管道绑定启动时的 revision；发生新选择、超过 16 MiB 或 10 秒未读完时丢弃旧读取。
- 浏览器收到的内容带 `revision` 和 `origin`。`origin=browser` 不再写回本机；自动写入要求当前视图可见、活动且远端输入区域获得焦点。本地编辑器、终端和复制辅助面板获得焦点时不接纳新的自动复制。异步写入串行执行，只保留最新待写版本，并用操作代次丢弃尚未执行的旧写入。
- 不再依赖焦点事件中的 `readText()` 预同步，不保留 500 毫秒 blanket suppression，也不使用文本相等代替远端应用确认。
- Ctrl+C/X 后紧接 Ctrl+V 时，粘贴等待该远端复制的 selection 回传，避免使用尚未更新的本机剪贴板。若本机写入失败，在当前远端上下文仍可使用已确认的复制内容；应用菜单复制回传的文本也支持这种回退。离开该输入上下文即取消此粘贴意图，后续外部复制的内容来自本次原生 `paste` 事件。
- 失焦、本地编辑器获得焦点、页面隐藏、切换视图、连接关闭均取消未完成远端输入并释放按键。页面销毁清理监听器；重连丢弃旧连接回调和残余剪贴板分块。已经派发给应用的操作不回滚。
- 浏览器已经受理的 `writeText()` 没有可靠取消接口；过期完成结果不得清除新版本提示或触发后续旧写入。

## 复制到本机的兼容处理

复制同步与粘贴事务分别管理。`clipboard.js` 维护远端复制意图、最新手动复制快照和本机写入任务；`clipboard-ui.js` 负责双语提示及可见文本面板。服务端协议保持兼容。

1. 收到有效远端文本后，检测安全上下文、写入 API、可识别的页面权限策略及已知写入权限。普通 HTTP 域名/IP 通常没有异步 Clipboard API；可信 localhost 是例外。Permissions API 不支持 `clipboard-write` 查询时按“未知”处理。
2. 可自动写入时串行调用 `writeText()`。非安全上下文、API 缺失、已确认权限拒绝、已确认策略限制分别说明；无法确认原因的 `NotAllowedError` 使用“浏览器阻止了自动复制”，其他异常使用“未能完成自动复制”。不会一律要求用户检查权限。
3. 失败后在所属视图显示一条可操作提示，不自动抢焦点。连续复制更新同一提示。“复制到本机”在真实点击的调用栈内直接发起写入，不等待权限查询，也不重新发送远端复制/剪切按键。写入过程中禁止并发重试，成功后恢复远端输入焦点。
4. “手动复制”展示只读文本框并选中文本，支持 Ctrl/Cmd+C、右键菜单及原生文本选择。采用用户触发的浏览器复制事件，适用于 HTTP 或异步写入被拒绝的环境。空文本在原生 `copy` 事件内提供空 `text/plain`，避免留下旧内容。没有后台隐藏 textarea/`execCommand` 回退，也不会申请读取权限来验证写入。
5. 面板中的文本在操作期间保持稳定。关闭按钮、Escape 或点击面板外只关闭本次复制面板；外部点击被消费，避免穿透到应用或其他弹窗。复制控件沿用本地输入白名单，快捷键不发送给远端。
6. 全屏时出现复制提示会解除鼠标/键盘锁定，保留远端输入焦点，让用户能够点击复制控件；提示显示期间不重新锁定。嵌入视图将面板挂载到当前全屏视频容器，退出全屏后恢复挂载位置及面板内焦点。

手动快照仅存于当前视图内存，单份不超过 16 MiB；不写入本地存储、日志或父 iframe。窗口失焦/页面隐藏会暂停自动写入并清除远端粘贴意图，但保留可供用户主动处理的快照，返回后不自动重试。进入复制控件保留快照；进入其他本地编辑器、关闭提示、切换视图、断线、重连或关闭同步则清理快照。外部新粘贴会清除旧提示。

复制回包超时使用独立的 `remote_copy_timeout`。依赖该内容的粘贴显示“未收到远端复制文本，请重新复制”；单独 Ctrl+C 没有回包时不主动报错，因为它也可能是应用的中断命令或没有选区。诊断仅记录写入阶段、原因、标准异常类型、安全上下文、焦点、用户激活和已知权限状态，不记录文本。

## 兼容边界

旧 `cw/c/cws/cwd/cwe` 文本协议保留，统一走输入队列，在真正应用后广播。旧前端原先“按键先发”的竞态仍需升级前端才能解决。

新前端只对支持 paste v1 的服务器启用跨端粘贴；旧服务器会得到升级提示，避免悄悄粘贴旧内容。服务端显式关闭剪贴板同步时，保留远端原生快捷键语义。

文本回传支持原来的裸 base64 以及带元数据的 JSON。分块使用 4095 字节，使中间 base64 块没有 padding，兼容旧客户端先拼接再解码的方式。

原生远端应用的菜单操作继续使用应用自身的剪贴板；跨端内容绑定适用于 Web 捕获到的粘贴手势。HTML/PNG 通过下文的可选 MIME 扩展进入同一事务；文件上传保持独立通道，不把文件路径解释为剪贴板内容。

## HTML / PNG 扩展

paste v1 的 `clipboard_caps` 可附带 `mime_types`。二进制开关打开时为 `text/plain`、`text/html`、`image/png`，关闭时只有纯文本；运行时切换会主动广播更新能力，无需重连。新前端只向声明此能力的服务器发送可选的 start `formats: [{mime, size}, ...]`，传输体按这个顺序拼接；旧文本请求不带 formats，保持兼容。服务器校验类型白名单、去重、总长度、文本 UTF-8 和 PNG 签名，所有表示共享一个 selection revision 和送达确认。总大小仍为 16 MiB，不接纳 `text/uri-list` 或任意文件路径。

远端复制会并行读取同一 revision 下的可用表示，所有非阻塞管道结束后一次回传。原有纯文本消息不变；多表示使用带 formats、revision、origin 的 clipboard_start 元数据，后接原有 data/finish 分块。任何新 selection、超时、超限或读取错误都会丢弃该次读取。二进制开关关闭时不回传 HTML/PNG。

本机通过 `ClipboardItem` 一次写入受支持的 MIME；缺少相关 API 时保留可用纯文本回退。纯图片在权限受限时提供用户主动重试入口，不显示文本选择面板。旧 cb/cbs/cbd/cbe 入口同样经过输入队列直接设置合成器 selection，不再依赖 wl-copy；它们只更新 selection，不替代带粘贴意图的事务。
