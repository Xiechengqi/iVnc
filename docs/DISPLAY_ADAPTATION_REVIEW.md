# 独立客户端显示适配：实现与 Review

日期：2026-11-13。基础提交：`db36cd4`。Review 已完成，未发现尚未处理的阻断问题。工作区原有的 Safari toolbar 点击与整标签排序修改已保留，并纳入回归。

## 实现结果

- 主桌面和各共享应用分别持有固定逻辑尺寸。连接、刷新、横竖屏、DPR、全屏及工具栏高度变化只重排当前客户端。
- 默认完整等比居中显示，可切换视频原始像素及滚动；模式保存在浏览器。共享和远程 iframe 使用同一规则，切换和重排保留连接。
- 合成器尺寸、编码尺寸和客户端工作区分离。低 H.264 接收能力只缩小编码输出，退出后恢复质量，原生应用布局保持不变。
- 控制台可以明确修改主桌面或本地共享应用的尺寸，保存后重启恢复；远程应用由来源实例管理。锁定配置优先于保存值。
- 输入以桌面坐标及几何版本传递。空白区不发送指针输入，拖拽移出仍可释放；触摸、笔、相对移动和旧协议均有对应换算。
- 终端与控制台按浏览器 CSS 像素和工作区布局，视频缩放不改变本地文字大小或选区坐标。

配置优先级、范围限制、API 和兼容规则见 [显示适配说明](DISPLAY_ADAPTATION.md)。

## Review 核对与修正

| 核对项 | 结论与证据 |
| --- | --- |
| 全局尺寸入口 | DataChannel 的旧 `r` 不调整桌面；新 `_viewport` 仅记录诊断。只有管理 API 入队实际修改。真实多客户端刷新、旋转和旧消息均不改变输出。 |
| 事务与持久化 | 预分配新缓冲，启动新编码管线并应用输出后原子保存；失败恢复旧缓冲与管线，不递增版本。真实制造保存路径失败后，窗口、视频、输入和文件内容均恢复。 |
| 并发与资源 | 使用版本和单个待处理请求拒绝冲突，验证偶数宽高、轴上限及总像素。流参数和尺寸保存串行合并，临时文件权限为 0600。 |
| 管理边界 | 补齐 worker 内部路径允许列表的 display 端点，继续经过 Basic Auth 和控制台访问限制；app-view/remote 网关不开放此端点。单元与真实共享应用检查通过。 |
| 错误与控制台恢复 | 上次修改失败使用 `last_error`，避免正常状态查询被通用 HTTP 错误处理误判。控制台打开时若另一修改尚未完成，会继续查询并恢复表单；范围变化和旧响应使用 generation 隔离。 |
| 输入过渡 | 在服务器入队和消费时校验版本；桌面变化释放输入并等待新帧。编码尺寸单独变化时继续按当前图像映射，不丢弃正在拖拽的松开事件。新增 Chromium/WebKit 场景确认。 |
| 本地弹窗 | 实测发现 CSS transform 会使 xterm 选区偏离鼠标。弹窗改用独立的 CSS 工作区布局，真实选择、复制、PTY 尺寸、拖动、还原和全屏均通过。 |
| 生命周期 | 清除旧自动尺寸逻辑的清理函数和变量残留；保留视口、视频 metadata、DPR 和滚动监听的销毁路径。工具栏紧凑菜单中的显示模式文字同步更新。 |
| 既有行为 | 原有排序、改名、Safari 点击稳定性、剪贴板事务、手势、终端透明度/置顶和共享视图保留均完成对应回归。 |

真实浏览器脚本也更新为新协议和坐标规则：滚轮明确落在视频内，等待共享视频解码后执行手势，指针监测识别版本包装，管理尺寸使用显式 API。窗口测试按实际工作区验证拖动并避开固定导航栏，保留原有功能断言。

## 验证边界

仍共用一路编码流，低解码能力客户端可能降低所有连接的视频清晰度、帧率或码率；应用的布局也仍由同一逻辑桌面决定。此轮提供客户端独立缩放显示，不提供同一原生窗口的多套独立布局或每客户端编码。

本地浏览器验证环境为 Linux Chromium/WebKit，未进行 macOS Safari 真机验收。现有新增 CI 包含 macOS Chromium/WebKit，但远端工作流尚未在本地执行。Safari 真机仍应补充同时连接、刷新、缩放、全屏和应用切换验证。
